# Деплой ИИ-ассистента и API записи на Render

## Как это устроено

```
 msnails.eu (GitHub Pages)          Render (Node, этот server.js)             Сервисы
 iOS-виджет + кнопка ассистента ──► /availability  /book  /agent/chat ──┬──► Anthropic API (Claude)
                                                                         ├──► Telegram-бот → сообщение Марии
                                                                         └──► приватный репозиторий ms-nails-bookings
                                                                              (bookings.json) ◄── SMS-напоминания (GitHub Actions)
```

* Сайт остаётся на GitHub Pages. На Render живёт только API.
* Render **заменяет Cloudflare Worker**: тот же формат записей, тот же приватный репозиторий, поэтому SMS-напоминания
  из `.github/workflows/sms-reminders.yml` продолжают работать без изменений. Worker после перехода не нужен.
* Файловая система Render временная, поэтому в продакшене записи **обязательно** хранятся в GitHub (шаг 3).
* Конфигурация сервиса: [`render.yaml`](../../render.yaml) в корне репозитория.

## Шаг 1. Telegram-бот через @BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) (с синей галочкой) и отправьте `/newbot`.
2. **Name** (имя в чатах): `MS Nails Записи`.
3. **Username**: латиницей и обязательно с `bot` на конце, например `msnails_booking_bot`. Если занято, BotFather попросит другое.
4. BotFather пришлёт **токен** вида `123456789:AAH...`. Это пароль к боту: не публикуйте его и не вставляйте в код.
   Если токен утёк: у BotFather `/revoke`, выберите бота, и выпустится новый.
5. **Мария** открывает бота по ссылке `t.me/<username>` и нажимает **Start**. Пока она этого не сделала, бот не сможет ей писать.
6. Узнайте **chat_id**: откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.
   Найдите `"chat":{"id": 123456789 ...}` и скопируйте число. Если ответ пустой (`"result":[]`), отправьте боту любое сообщение и обновите страницу.
   * Хотите получать записи в группу: добавьте бота в группу, напишите там сообщение и возьмите id из `getUpdates`. У групп он отрицательный (`-100…`).
7. Проверка (подставьте свои значения):
   `https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=<CHAT_ID>&text=test`. Сообщение должно прийти в Telegram.

## Шаг 2. Ключ Anthropic

1. [console.anthropic.com](https://console.anthropic.com) → **API keys** → **Create key**, скопируйте `sk-ant-…`.
2. В **Settings → Limits** задайте месячный лимит расходов (например 20 $), чтобы обезопасить бюджет от злоупотреблений чатом.

## Шаг 3. Хранилище записей (GitHub)

Если приватный репозиторий и токен уже созданы по [booking/README.md](../README.md) (шаги 1–2), используйте их.
Иначе:

1. Создайте **приватный** репозиторий `ms-nails-bookings` (с галочкой «Add a README»).
2. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate:
   Only select repositories → `ms-nails-bookings`, права **Contents: Read and write**, максимальный срок.
   Скопируйте токен: это `GITHUB_TOKEN` для Render.

## Шаг 4. Создание сервиса на Render

1. Зарегистрируйтесь на [render.com](https://render.com) (удобно через GitHub).
2. **New +** → **Blueprint** → подключите репозиторий сайта (`rustams060575-bot/ms-nails-academy`).
   Render найдёт `render.yaml` и покажет сервис `ms-nails-agent`.
3. Render попросит значения секретов. Введите их (в таблице ниже, значения без кавычек):

| Переменная | Значение | Откуда |
|---|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-…` | шаг 2 |
| `GITHUB_TOKEN` | токен GitHub | шаг 3 |
| `TELEGRAM_BOT_TOKEN` | `123456789:AAH…` | шаг 1 |
| `TELEGRAM_CHAT_ID` | число | шаг 1 |

   Остальные переменные уже заданы в `render.yaml`:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `NODE_ENV` | `production` | продакшен-режим (слушает `0.0.0.0`, доверяет IP из заголовка прокси) |
| `SERVE_SITE` | `false` | в продакшене сайт не раздаётся: он на GitHub Pages |
| `ALLOWED_ORIGINS` | `https://msnails.eu,https://www.msnails.eu` | с каких сайтов браузер может обращаться к API; остальные получают 403 |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | модель ассистента |
| `BOOKINGS_REPO` | `rustams060575-bot/ms-nails-bookings` | приватный репозиторий с записями |
| `BOOKINGS_PATH`, `BOOKINGS_BRANCH` | `bookings.json`, `main` | файл и ветка |
| `NODE_VERSION` | `22` | версия Node |

4. Нажмите **Apply**. Через 1–2 минуты сервис получит адрес вида `https://ms-nails-agent.onrender.com`.
   Если имя `ms-nails-agent` занято, Render добавит суффикс: используйте тот адрес, который он показал.

> Подсказка: переменные можно менять позже в Render → сервис → **Environment**. После изменения сервис перезапустится сам.

## Шаг 5. Проверка сервера

1. Откройте `https://<ваш-адрес>.onrender.com/healthz`. Ожидаемый ответ:
   `{"ok":true,"service":"ms-nails-agent","mode":"claude","storage":"github","telegram":true}`
   * `mode: "demo"` → не подхватился `ANTHROPIC_API_KEY`.
   * `storage: "file"` → не заданы `GITHUB_TOKEN` или `BOOKINGS_REPO`. Записи пропадут при перезапуске, это недопустимо.
   * `telegram: false` → не заданы `TELEGRAM_BOT_TOKEN` или `TELEGRAM_CHAT_ID`.
2. `https://<ваш-адрес>.onrender.com/availability` должен вернуть JSON со свободными слотами.
3. Логи: Render → сервис → **Logs**. При старте сервер печатает режим, хранилище, Telegram и CORS.

## Шаг 6. Подключение сайта (после успешной проверки)

Сейчас эти правки в репозиторий **не внесены**: сайт на GitHub Pages ещё работает по-старому (резерв через WhatsApp).
Когда сервер проверен, сделайте в `index.html`:

1. В `<head>` перед `</head>` добавьте (подставьте свой адрес Render):
   ```html
   <script>window.MS_AGENT_API='https://ms-nails-agent.onrender.com';</script>
   <link rel="stylesheet" href="/booking/agent/agent.css">
   ```
2. Перед `</body>` добавьте:
   ```html
   <script src="/booking/agent/agent-widget.js" defer></script>
   ```
3. В последнем `<script>` вместо пустого адреса впишите тот же:
   ```js
   var BOOKING_API = 'https://ms-nails-agent.onrender.com';
   ```
4. Пересоберите языковые версии: `node tools/build-seo.mjs` (или `npm run seo`).
5. Закоммитьте и запушьте. Через минуту сайт на msnails.eu покажет кнопку ассистента, а виджет начнёт писать в продакшен-API.
6. Сделайте тестовую запись на сайте и в чате с ассистентом: должно прийти сообщение в Telegram, а в `ms-nails-bookings` появиться коммит.
   Тестовую запись отмените в `bookings.json` (`"status": "cancelled"`).

## Шаг 7. Treatwell, Telegram-бот Афины и почта (работа 24/7)

Один сервис Render делает три фоновые вещи: слушает бота (/start, кнопки), каждые 60 секунд забирает письма Treatwell
из ящика Афины по IMAP и принимает вебхук `/api/external-booking/*`. Всё это работает, только пока сервис **не спит**.

### Переменные окружения (Render → сервис → Environment)

| Переменная | Значение | Примечание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен `@ms_nails_booking_bot` из BotFather | секрет. Должен быть токеном именно этого бота |
| `TELEGRAM_BOT_USERNAME` | `ms_nails_booking_bot` | в `render.yaml` |
| `TELEGRAM_CHAT_ID` | Telegram-ID Марии (`7012959995`) | запасной получатель, пока в конфигурации нет привязки |
| `IMAP_USER` | `athena.msnails@gmail.com` | в `render.yaml` |
| `IMAP_PASSWORD` | пароль приложения Google (16 букв) | секрет, не обычный пароль |
| `EXTERNAL_BOOKING_TOKEN` | длинный случайный ключ | секрет. Без него `/api/external-booking*` в продакшене выключен (503) |
| `ADMIN_TOKEN` | длинный случайный пароль | секрет. Нужен для `/api/admin/*` и кабинета `/admin` |
| `GITHUB_TOKEN`, `BOOKINGS_REPO` | как в шаге 3 | записи и `config.json` (привязка Марии) хранятся в приватном репозитории |
| `ANTHROPIC_API_KEY` | ключ Anthropic | как раньше |
| `ATHENA_EMAIL` | `athena.msnails@gmail.com` | только для вывода в лог |

Остальные переменные (`NODE_ENV=production`, `SERVE_SITE=false`, `ALLOWED_ORIGINS`…) уже в `render.yaml`.
Случайный ключ: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`.

### Порядок деплоя
1. **Остановите локальный сервер** (`node booking/agent/server.js`). С одним токеном бота и одним ящиком работать должен только один экземпляр:
   иначе Telegram вернёт конфликт 409, а письма обработаются дважды (повторная бронь с тем же кодом отсеивается).
2. Сделайте push в `main` (автодеплой Render). Если сервис создан из Blueprint, Render запросит значения секретов `sync: false`.
   Если сервис создан вручную, добавьте переменные из таблицы сами (Environment → Add Variable) и нажмите **Save, rebuild, and deploy**.
3. В логах (Logs) найдите строки:
   - `Telegram-бот: @ms_nails_booking_bot · ждёт /start …`
   - `[IMAP] ✓ Подключение к imap.gmail.com:993 успешно · ящик athena.msnails@gmail.com …`
   - `Treatwell: приём писем включён`
4. **Привяжите Марию заново** (на Render пока нет `config.json` с её привязкой):
   ```
   curl -X POST https://<ваш-адрес>.onrender.com/api/admin/generate-link -H "Authorization: Bearer <ADMIN_TOKEN>"
   ```
   Отправьте полученную ссылку Марии. После Start она станет администратором, а кнопки «Принято» / «Снять блок» заработают.
   Проверка: `GET /api/admin/status` с тем же заголовком вернёт `"bound": true`.
5. В Treatwell Connect укажите адрес `athena.msnails@gmail.com` для уведомлений о бронях.
6. Проверьте на первой настоящей брони: в логах `[ПОЧТА] Treatwell T…: слот … свободен, бронь принята`, у Марии сообщение с кнопками.

### Чтобы бот и почта работали 24/7
* **Тариф Starter** (~7 $/мес) — единственный надёжный вариант: сервис не засыпает, опрос почты и бот идут непрерывно.
* На бесплатном тарифе сервис засыпает через 15 минут без запросов. Пока он спит, бот молчит (нажатия кнопок и /start ждут до 24 ч),
  а письма просто лежат в ящике до пробуждения. Обход — пинг `/healthz` каждые 5 минут через UptimeRobot, но это полумера
  (лимит бесплатных часов, перезапуски).
* При деплое новый экземпляр на минуту работает вместе со старым: бот сообщит о конфликте 409 и повторит попытку через минуту. Это нормально.
* `TELEGRAM_BOT_POLLING=off` отключает приём сообщений ботом (например, для второго экземпляра). Для Treatwell-писем отдельного выключателя нет:
  просто не задавайте `IMAP_USER` / `IMAP_PASSWORD`.

### Бот и почта: только один экземпляр
Токен бота и ящик Афины читает один сервис. Локально приём сообщений бота (`TELEGRAM_BOT_POLLING=on`) и опрос почты (`IMAP_POLLING=on`)
**по умолчанию выключены**, чтобы локальный запуск не перехватывал сообщения у Render (конфликт 409, двойные уведомления).
В продакшене оба включены сами. При старте бот снимает старый вебхук (`deleteWebhook`), а при конфликте 409 повторяет попытку каждые 15 с:
во время деплоя старый экземпляр останавливается, и новый подхватывает бота без вмешательства.
`ATHENA_EMAIL` необязателен: если не задан, берётся `IMAP_USER` (адрес для Treatwell Connect — `athena.msnails@gmail.com`).

### Чек-лист: проверка приёма броней
1. `GET https://<адрес>/healthz` → `"ok": true`, `"storage": "github"`.
2. Логи: «[IMAP] ✓ Подключение…», «Telegram: бот слушает сообщения», нет повторяющегося «конфликт 409».
3. `GET /api/admin/status` (Bearer `ADMIN_TOKEN`) → `"bound": true` (иначе привяжите Марию по ссылке из шага 4).
4. Тест вебхука (создаст блок, потом снимите его отменой):
   ```
   curl -X POST "https://<адрес>/api/external-booking/email?key=<EXTERNAL_BOOKING_TOKEN>" -H "content-type: application/json"      -d '{"from":"noreply@treatwell.gr","subject":"Booking (Κωδ. T9000000001)","text":"Κωδ. T9000000001
Υπηρεσία: ТЕСТ
1 Δεκεμβρίου 2026 at 11:00
€0,00
ТЕСТ Афина
+30 000 000 0000
a@b.gr"}'
   ```
   Ответ 201, у Марии сообщение с кнопками «Принято» / «Снять блок». Тот же запрос второй раз → `"duplicate": true`.
   Повтор с другим кодом и тем же временем → 409 и уведомление о наложении.
5. Снять тест: кнопка «Снять блок» или письмо с «cancel» в теме и тем же кодом.
6. Почта: отправьте на `athena.msnails@gmail.com` письмо с настоящей брони Treatwell (или дождитесь первой). В течение минуты в логах `[ПОЧТА] Treatwell T…`.
7. Слот в `/availability?date=…` для заблокированного времени больше не предлагается.

### Безопасность
* Пароль приложения Google и токен бота лежат только в Environment Render и в локальном `.env` (он в `.gitignore`).
  Если они попали в переписку или лог, отзовите: пароль приложения — в настройках аккаунта Google, токен бота — командой `/revoke` в BotFather.
* Нажатия на кнопки принимаются только от привязанного администратора, письма — только от адресов `*@treatwell.*`.

## Запуск в продакшене: как работает и что учесть

* **Бесплатный тариф засыпает** после 15 минут без запросов, первый запрос после сна занимает около 50 секунд.
  Виджет покажет слоты с задержкой, а при таймауте (10 с) сработает резерв через WhatsApp. Решения:
  тариф **Starter** (~7 $/мес, не засыпает), либо бесплатный пинг `/healthz` каждые 5–10 минут через [UptimeRobot](https://uptimerobot.com).
  Для бизнеса рекомендуется Starter.
* **Автодеплой**: каждый push в `booking/**`, `server/**`, `render.yaml` или `package.json` пересобирает сервис (`server/**` тоже). Правки только в `index.html` его не затрагивают.
* **Защита**: CORS по `ALLOWED_ORIGINS`, лимит 20 запросов в минуту на IP, не больше 3 будущих записей на один номер.
  Лимиты хранятся в памяти и сбрасываются при перезапуске. Установите месячный лимит расходов в консоли Anthropic.
* **Сбой Telegram не отменяет запись**: он попадёт только в логи Render. Запись сохранена в `bookings.json`.
* **Локальная проверка перед деплоем**: скопируйте `.env.example` в `.env`, впишите `ANTHROPIC_API_KEY`, `TELEGRAM_*` и
  **оставьте `GITHUB_TOKEN` пустым**, иначе тестовые записи попадут в боевой репозиторий. Запуск: `node booking/agent/server.js`.
* **Cloudflare Worker** (`booking/worker`) после перехода на Render можно не разворачивать.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| В Telegram ничего не приходит | в логах `Telegram failed: 401` → неверный токен; `400 chat not found` → Мария не нажала Start или неверный `chat_id` |
| Виджет показывает «Не удалось отправить» / уходит в WhatsApp | API не отвечает (сервис спит) или домен сайта не входит в `ALLOWED_ORIGINS` (в консоли браузера ошибка CORS) |
| `/healthz` → `storage: "file"` | не заданы `GITHUB_TOKEN`/`BOOKINGS_REPO` |
| Ошибка в логах `GitHub read failed: 404` | неверное имя репозитория или у токена нет доступа к нему |
| Ассистент не отвечает, в логах `Anthropic 401/429` | неверный ключ или исчерпан лимит расходов |
| Сервис не стартует | Render → Logs; проверьте, что `startCommand` = `node booking/agent/server.js` |

## Напоминания клиентам (за 24 и за 12 часов)

Их отправляет GitHub Actions (`.github/workflows/sms-reminders.yml`, раз в 15 минут), а не Render. Логика в `booking/reminder/send-reminders.mjs`:

| Напоминание | Когда уходит |
|---|---|
| За 24 часа | визит завтра по афинскому календарю и осталось не больше 24 часов |
| За 12 часов | осталось от 1,5 до 12 часов, запись была создана ещё до отметки «12 часов до визита» (если записались позже, повторное сообщение сразу после записи было бы навязчивым), отправка только с 08:00 до 21:30 по Афинам |

Каждое уходит один раз (отметки `reminderSentAt` и `reminder12SentAt` в `bookings.json`), при сбое до 3 попыток, потом Мария получает предупреждение в Telegram. Тексты на греческом, слова «сегодня/завтра» подставляются по реальной дате.

Канал выбирается переменной **Actions → Variables** `REMINDER_CHANNEL`:

| Значение | Что делает |
|---|---|
| `sms` (по умолчанию) | только SMS (SMS.to или Twilio, см. `booking/README.md`, шаг 6) |
| `whatsapp` | только WhatsApp |
| `whatsapp_then_sms` | сначала WhatsApp, при ошибке SMS (рекомендую, когда WhatsApp будет настроен) |

Проверка без отправки: Actions → **SMS reminders** → Run workflow (галочка «dry run»).

## WhatsApp (необязательно, нужна настройка у Meta)

WhatsApp разрешает компаниям писать первыми только по заранее одобренным шаблонам. Поэтому нужна **WhatsApp Business Platform (Cloud API)**:

1. [business.facebook.com](https://business.facebook.com) → создать/выбрать Business Portfolio и пройти верификацию бизнеса.
2. [developers.facebook.com](https://developers.facebook.com) → My Apps → Create App (тип Business) → добавить продукт **WhatsApp**.
3. Подключить номер отправителя (не должен быть привязан к обычному приложению WhatsApp) и получить **Phone number ID**.
4. Создать постоянный токен: Business Settings → System users → создать пользователя → выдать доступ к приложению с правом `whatsapp_business_messaging` → Generate token. Это `WHATSAPP_TOKEN`.
5. Создать и отправить на одобрение два шаблона (категория **Utility**), одобрение занимает от минут до суток:

**Шаблон для клиента** (язык `el`), название, например, `visit_reminder`. Текст:
`MS Nails Academy: μικρή υπενθύμιση για το ραντεβού σας ({{1}}) {{2}} στις {{3}}, Λυκούργου 15, Περιστέρι. Σας περιμένουμε!`
Параметры: `{{1}}` услуга, `{{2}}` день (например «αύριο 07/11»), `{{3}}` время.

**Шаблон для Марии** (язык `ru`), название, например, `new_booking`. Текст:
`Новая запись: {{1}}, тел. {{2}}. {{3}}, {{4}} в {{5}}.`
Параметры: `{{1}}` имя, `{{2}}` телефон, `{{3}}` услуга, `{{4}}` дата, `{{5}}` время.

6. Переменные.
   * **Render** (уведомление Марии): `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_MARIA_TO` (номер Марии с кодом страны, например `+306939350160`), `WHATSAPP_TEMPLATE_MARIA` (`new_booking`), необязательно `WHATSAPP_MARIA_LANG` (по умолчанию `ru`).
   * **GitHub Actions** (напоминания клиентам): secret `WHATSAPP_TOKEN`, variables `WHATSAPP_PHONE_ID`, `WHATSAPP_TEMPLATE_REMINDER` (`visit_reminder`), `WHATSAPP_REMINDER_LANG` (`el`), `REMINDER_CHANNEL`.

Ограничения: WhatsApp взимает плату за каждый разговор по тарифам Meta, а шаблоны должны быть одобрены. Пока WhatsApp не настроен, Мария получает уведомления в Telegram (в нём есть и кнопка-ссылка на WhatsApp клиента), а клиенты получают напоминания по SMS. Код WhatsApp в проекте написан по документации Cloud API, но без ваших учётных данных я его вживую не проверял.

## Ассистент и форма записи

Когда клиент открывает чат, ассистент читает текущий выбор в виджете (услуга, дата, время, имя, телефон) и предлагает «Продолжить с моим выбором». Дальше он проверяет слот, собирает недостающее и оформляет запись после подтверждения. После записи в чате виджет сам обновляет свободные слоты.

## Постоянная память Афины и кабинет Марии

Память хранится **на сервере**, а не в браузере.

| Что | Где лежит | Зачем |
|---|---|---|
| Профили гостей | `memory/clients.json` | имя, телефоны, заметки о предпочтениях, когда была последний раз |
| Диалоги | `memory/chats/<clientId>.json` | последние 40 сообщений каждой гостьи, чат продолжается в другой день |
| Речевые паттерны Марии | `memory/patterns.json` | фразы и правила стиля, попадают в промпт после утверждения |
| Визиты | `bookings.json` | записи теперь содержат `clientId`, по ним Афина знает прошлые и будущие визиты гостьи |

* **Продакшен:** файлы лежат в той же папке приватного репозитория `ms-nails-bookings` (`GITHUB_TOKEN` и `BOOKINGS_REPO` уже заданы).
  Запись отложенная (раз в ~15 секунд и при остановке сервиса), записи на визит сохраняются сразу.
* **Локально:** `booking/agent/data/memory/` (в Git не попадает).
* **Узнавание:** при первом сообщении браузер получает случайный `clientId` (localStorage). Тот же ключ использует виджет записи.
  Закрыли вкладку, пришли на следующий день с того же устройства и браузера — Афина узнаёт гостью, помнит имя, предпочтения и визиты.
* **Другое устройство или очищенный браузер:** гостья не узнаётся. Это сделано намеренно: по одному набранному номеру телефона история
  не раскрывается, иначе чужие имена и визиты можно было бы узнать, просто введя чужой номер. Узнавание по номеру безопасно только
  с подтверждением кодом (SMS или WhatsApp). Это возможное следующее улучшение.
* **Что запоминает сама Афина:** инструмент `remember_about_client` сохраняет только то, что гостья сама сказала (имя, оттенки, форма, длина, аллергии,
  удобное время). Телефон и подробности здоровья она не записывает.
* **«Забудь меня»:** гостья просит, Афина переспрашивает и стирает профиль и историю (`forget_client`). Мария может сделать то же в кабинете.
  Важно: в Git-истории приватного репозитория старые версии файлов остаются. Для полного стирания нужна чистка истории репозитория.
  Для работы с личными данными (GDPR) разместите на сайте политику конфиденциальности и упомяните, что чат сохраняет переписку и предпочтения.
* **Ёмкость:** `clients.json` хранит все профили одним файлом (GitHub Contents API читает до 1 МБ напрямую, больше через raw — это обработано).
  Для сотен гостей этого достаточно. Если гостей станут тысячи, понадобится настоящая база данных.
* Профили, не появлявшиеся 18 месяцев, удаляются автоматически.

### Кабинет Марии: `https://<ваш-адрес>.onrender.com/admin`

1. В Render добавьте переменную **`ADMIN_TOKEN`**: длинный случайный пароль (например, 32+ символа). Без неё кабинет отключён.
2. Откройте `/admin` и введите токен.
3. **Импорт переписки:** вставьте экспорт чата WhatsApp («Экспорт чата» → «Без медиа») или Telegram, укажите имя Марии в чате
   и нажмите «Извлечь паттерны». На сервере из текста берутся только реплики Марии, из них убираются телефоны, e-mail и ссылки,
   затем Claude выделяет её правила стиля и лучшие дословные фразы. Всё попадает «на проверку».
4. **Проверка:** просмотрите найденное, отредактируйте или удалите лишнее, нажмите «Утвердить». Только утверждённое попадает в промпт Афины
   (до 12 правил и 14 фраз, приоритет фразам на языке гостьи). Можно добавить фразу вручную или утвердить сразу при импорте.
5. Дубликаты отбрасываются, имена клиенток в импортированных фразах нужно проверить глазами перед утверждением.

Как Афина «учится у Марии»: модель не дообучается сама. Паттерны пополняются там, где Мария реально общается (экспорт чатов в кабинет).
Подключение входящих сообщений WhatsApp или Telegram, чтобы паттерны собирались автоматически, технически возможно (через WhatsApp Business API),
но требует отдельной настройки.

Переменные: `ADMIN_TOKEN` (секрет, обязательно для кабинета), `MEMORY_DIR` (папка памяти в репозитории, по умолчанию `memory`).

## Записи без телефона (Афина)

Телефон не обязателен для записи через Афину. Если гостья не хочет оставлять номер сразу или просит записать её по имени, Афина соглашается,
подтверждает запись и благодарит, не отказывая и не отсылая никуда. Что происходит дальше:

* В Telegram админу уходит отдельное предупреждение **«⚠️ Запись БЕЗ телефона»** с именем, услугой, датой и временем.
* Напоминания за 24 и 12 часов для такой записи не отправляются (в `bookings.json` `phone` пустой).
* Когда гостья позже называет номер в чате, Афина вызывает `attach_phone`: номер добавляется к её последней предстоящей записи (по `clientId`),
  админу уходит сообщение **«📞 Гостья оставила телефон»**, и напоминания включаются.
* Для просьб, которые Афина не решает сама (отмена или перенос, вопрос вне прайса, лимит записей), есть инструмент `notify_maria`:
  сообщение **«💬 Просьба гостьи для Марии»** приходит в Telegram (не больше 5 в час на гостью). Гостью больше не отсылают в WhatsApp.
* Защита от злоупотреблений: без номера одной гостье (по `clientId` или имени) доступно не больше 2 будущих записей, с номером по-прежнему 3.
* Виджет записи на сайте работает как раньше и требует номер телефона.
